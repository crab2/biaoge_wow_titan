# bg次bis版 装备评分规则

> 状态：P0 规则已落地；升级分显示在表格和拍卖窗，物品 Tooltip 保持紧凑，其余明细展示待后续完善。
>
> 适用版本：`_classic_titan_`，以《巫妖王之怒》属性体系为基准。

## 1. 目标与边界

bg次bis版 的“装备评分”是**当前角色的个人升级分**，用于回答：

> 这件掉落装备替换我当前同部位装备后，是否值得我加价？

它不是以下内容：

- 不是全团统一的 GearScore；
- 不是只按品质、装等或副本阶段排序；
- 不是公开同步给团队的排名；
- 不是严格意义上的 BiS 证明，也不替代完整战斗模拟。

同一件装备对不同职业、天赋、职责、命中状态和自定义 EP 权重，可以得到不同的升级分。

评分流程固定为：

```text
物品元数据
  -> 可用性硬门槛
  -> 属性提取与规范化
  -> 当前角色权重
  -> 命中/精准/防御/破甲门槛折损
  -> 插槽与装等加分
  -> 与当前穿戴方案比较
  -> 显示升级分和解释
```

## 2. 对 AtlasLootMY 的参考结论

`AtlasLootMY` 中没有独立的 GearScore、Pawn 或 EP 评分公式。可复用的参考是**物品可用性和数据读取方式**：

| 参考位置 | 可借鉴规则 |
| --- | --- |
| `AtlasLootMY/Data/ClassFilter.lua` | 先检查职业要求，再检查装备位置、物品大类/子类和属性过滤 |
| `AtlasLootMY/Data/Requirements.lua` | 用物品数据中的职业位掩码判断职业限制；未知物品默认不阻断 |
| `AtlasLootMY/Core/ItemQuery.lua` | 物品信息和属性可能异步到达，不能把未加载视为“没有属性”并永久缓存 |
| `AtlasLootMY/Core/Tooltip.lua` | 装等从 `GetItemInfo` 获取，Tooltip 作为显示和兼容层 |
| `AtlasLootMY/Data/ClassFilter.lua` 的 `LINKED_STATS` | 同一属性存在完整名和 `_SHORT` 名时应视为同一属性 |
| `AtlasLootMY/Data/Token.lua`、`Data/ItemSet.lua` | 兑换物、套装是数据关系，不等同于属性评分公式 |

因此本规则沿用 AtlasLoot 的“可用性先行、属性规范化、异步数据安全”思路，但不直接把 AtlasLoot 的分类表当作 Titan 服的 EP 数据。评分权重仍由 bg次bis版 当前天赋 EP 表和角色自定义值决定。

AtlasLootMY 的默认属性过滤还会逐职业关闭明显无关的属性，例如战士/盗贼关闭智力，牧师/法师/术士关闭力量、敏捷、攻击强度、物理命中/暴击以及部分坦克属性。bg次bis版 不照搬这份静态开关，而是根据当前天赋和职责动态判断属性学派；这允许混合装备保留低权重属性，同时拒绝纯错误学派装备。

## 3. 角色评分档案

### 3.1 档案来源

每个角色保存一个本地档案，键为 `realmID/playerName`。档案不通过团队插件消息同步。

| 字段 | 含义 |
| --- | --- |
| `talentTab` | 1 到 3 的主天赋页；优先读取已有角色资料，否则取投入点数最多的天赋页 |
| `role` | `DPS`、`HEAL` 或 `TANK` |
| `specType` | `MELEE`、`RANGED` 或 `CASTER` |
| `isMT` | 坦克是否按主坦克防御门槛计算 |
| `dualWieldHit` | 近战命中门槛是否按双持 27% 计算 |
| `spellHit17` | 法术命中门槛是否按 17% 计算；关闭时按 14% 计算 |
| `caps` | 用户覆盖的命中、精准、防御、破甲门槛 |
| `epWeights` | 按“职责:天赋页”保存的自定义 EP |
| `bias1/bias2` | 没有专用 EP 时的第一、第二属性偏向 |

### 3.2 职业与天赋默认职责

| 职业 | 天赋 1 | 天赋 2 | 天赋 3 |
| --- | --- | --- | --- |
| 战士 | DPS / 近战（武器） | DPS / 近战（狂怒） | TANK / 近战（防护） |
| 圣骑士 | HEAL / 法系（神圣） | TANK / 近战（防护） | DPS / 近战（惩戒） |
| 猎人 | DPS / 远程（野兽控制） | DPS / 远程（射击） | DPS / 远程（生存） |
| 盗贼 | DPS / 近战（刺杀） | DPS / 近战（战斗） | DPS / 近战（敏锐） |
| 牧师 | HEAL / 法系（戒律） | HEAL / 法系（神圣） | DPS / 法系（暗影） |
| 死亡骑士 | TANK / 近战（鲜血）；允许切换 DPS | DPS / 近战（冰霜） | DPS / 近战（邪恶） |
| 萨满 | DPS / 法系（元素） | DPS / 近战（增强） | HEAL / 法系（恢复） |
| 法师 | DPS / 法系（奥术） | DPS / 法系（火焰） | DPS / 法系（冰霜） |
| 术士 | DPS / 法系（痛苦） | DPS / 法系（恶魔学识） | DPS / 法系（毁灭） |
| 德鲁伊 | DPS / 法系（平衡） | DPS / 近战（野性）；允许切换 TANK | HEAL / 法系（恢复） |

角色可以手动切换天赋页。手动切换后档案被锁定，直到用户再次选择天赋或重置配置。

### 3.3 主属性和默认偏向

主属性仅用于插槽固定价值和没有专用 EP 时的回退偏向：

- 治疗或法系：`INT`；
- 战士、圣骑士、死亡骑士：`STR`；
- 萨满近战：`STR`；
- 德鲁伊坦克：`AGI`；
- 远程、盗贼、猎人、非坦德鲁伊：`AGI`；
- 其他情况：`STR`。

没有专用 EP 时，默认第一/第二偏向为：

| 档案 | 第一偏向 | 第二偏向 |
| --- | --- | --- |
| 坦克 | 耐力 | 躲闪 |
| 治疗 | 法强 | 急速 |
| 法系输出 | 法强 | 急速 |
| 远程输出 | 破甲 | 暴击 |
| 近战输出 | 破甲 | 急速 |

第一偏向乘 `1.45`，第二偏向乘 `1.18`。两个偏向相同时只乘一次。

## 4. 可用性硬门槛

硬门槛在评分之前执行。命中任何一项时，装备不显示升级分，并返回一个明确原因。

### 4.1 物品大类

- 只把物品类型 `2`（武器）和 `4`（护甲）视为可评分装备。
- 宝石、消耗品、材料、任务物品、坐骑等返回“不是装备”。
- 元数据尚未加载时，使用 `GetItemInfoInstant` 补齐位置、大类和子类；仍缺失时等待后重算，不应把缺失数据永久当成 0 属性。

### 4.2 职业、装备位置和物品要求

按以下顺序检查：

1. 物品 Tooltip 中的职业限制是否包含当前职业；
2. 物品是否有红色的等级、声望、技能或其他装备要求；
3. “唯一可装备”或“已学会”提示不应被误判为不可用；
4. 物品位置是否能映射到一个或两个角色装备栏。当前代码对无法映射的位置旧分按 0 处理；拟优化后改为明确拒绝并提示“无法比较装备栏位”。

AtlasLootMY 的对应原则是 `Requirements.ClassCanUseItem` 加 `itemEquipLoc/itemClass/itemSubClass` 三层检查。

### 4.3 护甲类型

护甲子类约定为：`1=布甲`、`2=皮甲`、`3=锁甲`、`4=板甲`。默认职业护甲如下：

| 职业 | 默认护甲 |
| --- | --- |
| 战士、圣骑士、死亡骑士 | 板甲 |
| 猎人、萨满 | 锁甲 |
| 盗贼、德鲁伊 | 皮甲 |
| 法师、牧师、术士 | 布甲 |

例外：

- 项链、戒指、饰品、披风、护符/圣物、盾牌、持握物、徽记、衬衣等位置不检查护甲子类；
- 护甲子类 `0`（杂项/通用）放行；
- 其他护甲子类必须与职业默认护甲一致。

### 4.5 属性学派和“完全不需要”属性

护甲类型正确并不代表适合当前天赋。对项链、戒指、饰品等不带护甲类型的物品，使用**严格属性禁用检查**。装备位置不能绕过这一步，戒指也不能因为“人人都能戴”而被推荐给错误职业。

| 属性组 | 成员 |
| --- | --- |
| 法系/治疗 | `INT`, `SPI`, `SP`, `HEAL`, `HIT_SPELL`, `MP5`, 法术暴击/法术急速 |
| 坦克 | `STA`, `DEFENSE`, `DODGE`, `PARRY`, `BLOCK`, `BLOCKVALUE`, `ARMOR` |
| 物理 | `STR`, `AGI`, `AP`, `EXPERTISE`, `ARPEN`, `DPS`, 物理/远程命中、物理/远程暴击/急速 |
| 法术穿透 | `SPELLPEN`；必须单独识别，不能因未进入 EP 表而当作“无属性” |

对每个档案，先把该档案**完全不需要**的属性列入禁用集合。禁用属性的权重固定为 0，且不能通过装等分或插槽分伪装成升级。

| 当前档案 | 完全不需要、不得贡献分数的属性 |
| --- | --- |
| 物理近战/远程输出 | `SP`, `HEAL`, `HIT_SPELL`, 法术暴击、法术急速、`SPELLPEN` |
| 法系输出/治疗 | `AP`, 远程攻强、`ARPEN`, `EXPERTISE`、物理命中、物理暴击、物理急速 |
| 治疗 | 通用/物理/法术命中、`SPELLPEN`；治疗评分不为命中保留低保权重 |
| 非坦克（所有 DPS/治疗） | `DEFENSE`, `DODGE`, `PARRY`, `BLOCK`, `BLOCKVALUE` 及仅用于坦克的防御词缀 |
| 非德鲁伊 | `FERAL_AP`、猎豹/熊形态专属攻强 |

过滤原则：

- 禁用属性永远按 0 分处理，不得因为它们抬高候选装备分数；
- 物品除禁用属性外没有任何正权重属性时，直接拒绝，原因是“属性不适合你的天赋”；
- 纯法系件给物理职业、纯物理件给法系职业、纯坦克防御件给非坦克，必须拒绝；
- 混合属性装备只有在至少含有一个当前档案允许且权重大于 0 的属性时才可继续评分；禁用部分只作为浪费，不参与得分；
- 未识别但已知为禁用的属性（尤其法术穿透）必须先保留为 `SPELLPEN` 等字段，再参与拒绝判断，不能被“未列入规范字段、分值为 0”的兜底规则吞掉。

这比 AtlasLootMY 的“逐属性开关”更偏向评分用途：AtlasLoot 可以让用户单独隐藏某个属性，而 bg次bis版 还必须在戒指等通用部位执行职责级硬禁用，避免出现“装等高所以推荐错误属性”的结果。

### 4.6 唯一、兑换物和双槽替换

- 如果物品标记为唯一可装备且当前角色已经装备同一个物品，结果为“已装备唯一”，升级分固定为 0。
- 如果掉落物是兑换物，遍历当前副本的兑换关系，分别评分所有可兑换成品，取真实升级分最高的成品；Tooltip 显示“兑换为”提示。
- 戒指和饰品分别枚举两个栏位，按替换后的真实边际收益选择栏位，不按旧装备的孤立分数猜测。
- 单手武器只枚举当前职业/专精可合法使用的主手和副手栏位；不能双持的档案只比较主手。
- 双手武器按同时替换主手和副手的整体方案比较，候选武器自身只计分一次。

## 5. 属性提取与规范化

### 5.1 数据来源优先级

1. `GetItemStats(link)` 获取结构化属性；
2. Tooltip 扫描补齐 Titan/Classic 中结构化 API 没有返回的绿字；
3. 两份数据同名属性取绝对值较大的一个，避免重复相加；
4. 完成特殊属性归并后写入缓存。

属性缓存必须以能区分随机附魔/宝石的完整物品链接或规范化 item string 为键；如果只使用 itemID，未来出现同 ID 不同词缀时会串分。

### 5.2 规范化字段

| 规范字段 | 接受的典型来源 |
| --- | --- |
| `STR` | Strength、力量 |
| `AGI` | Agility、敏捷 |
| `STA` | Stamina、耐力 |
| `INT` | Intellect、智力 |
| `SPI` | Spirit、精神 |
| `AP` | Attack Power、Melee/Ranged Attack Power、攻击强度 |
| `RAP` | 远程攻击强度；评分时可按猎人档案归并为 `AP`，但在法系/治疗禁用检查中必须保留来源类别 |
| `SP` | Spell Power、Spell Damage、法术强度/法术伤害 |
| `HEAL` | Spell Healing、治疗效果/治疗强度 |
| `HIT` | 不限定学派的通用命中等级 |
| `HIT_PHYSICAL` | 物理/近战/远程命中等级；通过禁用检查后按 `HIT` 权重评分 |
| `HIT_SPELL` | 法术命中等级 |
| `CRIT` | 不限定学派的通用暴击等级 |
| `CRIT_PHYSICAL` / `CRIT_SPELL` | 物理或法术暴击；通过禁用检查后按 `CRIT` 权重评分 |
| `HASTE` | 不限定学派的通用急速等级 |
| `HASTE_PHYSICAL` / `HASTE_SPELL` | 物理或法术急速；通过禁用检查后按 `HASTE` 权重评分 |
| `ARPEN` | Armor Penetration、护甲穿透/破甲等级 |
| `SPELLPEN` | Spell Penetration、法术穿透；当前版本必须识别，即使默认权重为 0 |
| `EXPERTISE` | Expertise、精准等级 |
| `DEFENSE` | Defense Skill Rating、防御等级 |
| `DODGE` | Dodge Rating、躲闪等级 |
| `PARRY` | Parry Rating、招架等级 |
| `BLOCK` | Block Rating、格挡等级 |
| `BLOCKVALUE` | Block Value、格挡值 |
| `ARMOR` | Armor、护甲；不包括护甲穿透 |
| `MP5` | Mana Regeneration、每 5 秒恢复 |
| `DPS` | Damage Per Second、武器每秒伤害 |
| `SOCKET` | 每个空的红/黄/蓝/多彩/棱彩/无色插槽计 1 |

### 5.3 Tooltip 跳过规则

以下文本不作为静态属性加入：

- “使用：/Use:”效果；
- 几率触发、命中触发、装备触发等 proc 文本；
- 镶孔奖励/Socket Bonus；
- 非德鲁伊装备上的猎豹、熊形态或 Feral AP 文本；
- 把“护甲穿透”误识别成“护甲”的行。

饰品和戒指如果检测到触发特效，只增加 `proc` 说明，不在当前规则中估算触发收益。

### 5.4 特殊归并

- `FERAL_AP` 只有德鲁伊转成 `AP`，其他职业丢弃；
- 法术/物理/远程命中、暴击、急速在归并到 `HIT/CRIT/HASTE` 前必须保留来源学派；通用属性可以按当前档案使用，但法术暴击不能被当成物理暴击，反之亦然；
- `RAP` 可以在数值评分中归并为 `AP`，但职业禁用检查必须知道它原本是远程攻强；
- 盾牌、披风等不因护甲文本改变护甲类型判断；
- 坦克白字中数百点的异常值不得当成智力/精神；若明显与护甲重复，则归入 `ARMOR` 或丢弃重复字段；
- 未列入规范字段的属性当前分值为 0；但已知属于某职业禁用集合的属性必须阻断纯错误属性装备，不能因为解析失败而放行。

## 6. 权重模型

### 6.1 权重优先级

从高到低：

1. 当前角色档案中该“职责:天赋页”的自定义 EP；
2. 当前职业/天赋/职责的专用默认 EP；
3. `TANK`、`HEAL`、`MELEE`、`RANGED`、`CASTER` 通用回退权重；
4. 无专用 EP 时再应用主属性压低、治疗精神保底和偏向倍率。

专用 EP 来自当前代码的 `SPEC_EP`，数值是“每 1 点属性相对于基准属性的价值”，不是百分比。

无论默认 EP 还是自定义 EP，都必须再经过第 4.5 节的硬过滤。旧 EP 数据中与当前档案冲突的字段（例如物理档案的法强、治疗档案的命中）最终强制为 0。

### 6.2 通用回退权重

仅在没有专用 EP 时使用：

| 属性 | MELEE | RANGED | CASTER | HEAL | TANK |
| --- | ---: | ---: | ---: | ---: | ---: |
| `STR` | 1.00 | 0.10 | 0 | 0 | 0.35 |
| `AGI` | 1.00 | 1.00 | 0 | 0 | 0.40 |
| `STA` | 0.05 | 0.05 | 0.05 | 0.08 | 1.00 |
| `INT` | 0 | 0 | 0.55 | 0.70 | 0 |
| `SPI` | 0 | 0 | 0.10 | 0.90 | 0 |
| `AP` | 0.45 | 0.45 | 0 | 0 | 0.10 |

### 6.4 自定义 EP 和 Pawn 导入

- 自定义值覆盖同名默认值，未覆盖的属性保留默认值；
- 允许 0 和负数，负数可用于主动排斥属性；

- 导入文本未识别到任何有效权重时，不改变当前配置。

## 7. 评分公式

### 7.1 总公式

设物品属性为 `S`，权重为 `W`，当前角色相关评级为 `R`，门槛为 `C`，物品装等为 `iLvl`：

```text
总分 = 白字分 + 绿字分 + 插槽分 + 装等分
```

对非门槛属性：

```text
属性分(S, W) = S * W
```

对命中、精准、防御、破甲等门槛属性：

```text
缺口 = max(0, C - R)
有效量 = min(物品量, 缺口)
溢出量 = 物品量 - 有效量
门槛属性分 = 有效量 * W
```

也就是说，先读取当前角色属性；达到门槛后的多余点数完全不计分。未达到门槛时，也只计算补足缺口的部分。

### 7.1.1 函数式表达（Lua 风格伪代码）

下面的函数表达评分意图，实际实现还会先做物品类型、职业、护甲、武器和属性学派的可用性检查：

```lua
local function EffectiveAmount(stat, amount, profile, ratings)
    local cap = CapFor(stat, profile)
    if cap then
        local current = CurrentRating(stat, ratings)
        return math.min(amount, math.max(0, cap - current))
    end
    return amount
end

local function StatContribution(stat, amount, profile, ratings)
    local key = NormalizeStat(stat)
    if not IsAllowedStat(key, profile) then
        return 0
    end
    local value = EffectiveAmount(key, amount, profile, ratings)
    return value * (profile.weights[key] or 0)
end

local function GearScore(item, profile, ratings)
    local white, green = 0, 0
    for stat, amount in pairs(item.stats or {}) do
        local part = StatContribution(stat, amount, profile, ratings)
        if IsWhiteStat(NormalizeStat(stat)) then
            white = white + part
        else
            green = green + part
        end
    end

    local socket = (item.emptySockets or 0) * 16
        * (profile.weights[profile.primary] or 1)
    local ilvl = (item.itemLevel or 0) * 0.15
    return {
        total = white + green + socket + ilvl,
        white = white,
        green = green,
        socket = socket,
        ilvl = ilvl,
    }
end

local function UpgradeScore(candidate, equipped, profile, ratings)
    local baseline = RemoveEquippedRatings(ratings, equipped)
    local newScore = GearScore(candidate, profile, baseline).total
    local oldScore = 0
    for _, oldItem in ipairs(equipped) do
        oldScore = oldScore + GearScore(oldItem, profile, baseline).total
    end
    return newScore - oldScore
end
```

其中 `profile.weights` 的来源顺序是“当前角色自定义 EP → 当前职业/天赋/职责默认 EP → 通用回退权重”，`CapFor` 只为命中、精准、防御、破甲等门槛属性返回门槛值。`GearScore` 是一件装备在当前角色上的构成分，`UpgradeScore` 才是拍卖时用于判断是否值得加价的边际收益。界面最终对原始浮点分数四舍五入显示，但不会用装等单项替代属性价值。

### 7.2 门槛属性的适用范围

| 属性 | 适用档案 | 当前评级来源 | 默认门槛 |
| --- | --- | --- | ---: |
| 物理/远程命中 | 非治疗、非施法输出；远程使用远程评级 | 装备战斗评级 + 天赋/种族命中换算 | 263；勾选双持时 886 |
| 法术命中 | 法系输出 | 装备战斗评级 + 天赋/种族命中换算 | 368；勾选 17% 时 446 |
| 精准 | 近战和坦克 | `CR_EXPERTISE` | 214 |
| 防御 | 主坦克 | `CR_DEFENSE_SKILL` | 140 |
| 破甲 | 近战、远程、坦克且该档案权重大于 0 | `CR_ARMOR_PENETRATION` | 1400 |

特殊说明：

- 法系输出把 `HIT` 和 `HIT_SPELL` 相加后按法术命中门槛计入；治疗的所有命中均为 0 分；
- 物理/远程把 `HIT` 和 `HIT_PHYSICAL` 相加后按物理命中门槛计入；
- `dualWieldHit` 只应对近战双持档案开启，当前界面也只在近战或坦克档案显示；
- 主坦克防御按门槛折损；副坦克不做防御硬门槛，默认防御权重压到 `0.15`；
- 破甲只有当当前档案的 `ARPEN` 权重大于 0 时才启用门槛折损；
- 天赋命中和德莱尼种族命中先换算成评级并四舍五入，再与装备评级相加。

### 7.3 插槽与装等

```text
插槽分 = 空插槽数 * 16 * 主属性权重
装等分 = 物品装等 * 0.15
```

当前规则：

- 每个空插槽固定按 16 点“主属性等价值”计算；
- 不计算插槽颜色、插槽奖励和宝石本体的独立收益；
- Tooltip 中的 Socket Bonus 永远不重复计入；
- 装等分不区分部位，拿到有效 `iLvl` 就加入总分；
- 白字统计只包括 `STR/AGI/STA/INT/SPI/ARMOR`；绿字统计包括其他属性、插槽和门槛属性；装等分不归入白字或绿字。

### 7.4 评分示例

例 1：当前物理命中 200，装备提供 100 命中，门槛 263，命中权重 2：

```text
有效量 = 63
溢出量 = 37
命中分 = 63 * 2 = 126
```

例 2：装备提供 20 力量，力量权重 2，1 个空插槽，主属性权重 2，装等 213：

```text
力量分 = 20 * 2 = 40
插槽分 = 1 * 16 * 2 = 32
装等分 = 213 * 0.15 = 31.95
合计 = 103.95（界面显示为 104）
```

## 8. 当前装备比较

### 8.1 升级分

```text
升级分 = 替换方案中新装备的边际分 - 同一方案中旧装备的边际分
```

- 新分和旧分使用同一个角色档案、同一套权重，以及“当前整套评级减去该方案旧装备属性”得到的共同基线；
- 戒指、饰品和可双持的单手武器枚举合法栏位，选择升级分最高的真实替换方案；
- 空栏位旧分为 0；
- 升级分正数显示 `+N`，负数显示 `-N`，零显示 `+0`；
- “唯一已装备”不参与替换，显示 `=`；
- 不适合的装备不显示升级徽标；物品 Tooltip 不追加个人评分段。

### 8.2 显示与解释

物品 Tooltip 保留游戏原生装备信息和兑换/套装对照内容，不追加 bg次bis版 自身评分段；升级分、白字/绿字构成和属性价值在表格及拍卖窗中显示。

界面显示分数时使用 `floor(rawScore + 0.5)`，内部比较使用未取整的原始浮点数。

## 9. 当前明确不计分的内容

以下内容目前不会进入数值评分：

- 饰品主动使用和触发特效的平均收益；
- 套装 2/4/6 件效果；
- 物品附魔；
- 已镶嵌宝石的颜色、套装奖励和宝石特殊效果；
- 韧性、生命、法力上限等未纳入规范字段的属性；法术穿透虽然默认不计分，但必须作为 `SPELLPEN` 参与物理职业的错误属性过滤；
- 物品绑定、声望、任务线、外观和收藏价值；
- 物品名称中暗示的 BiS、阶段或价格；
- 默认专用 EP 中的武器 DPS。当前代码仍能提取 `DPS`，但专用 EP 应用前会移除 `dps`；仅未知职业回退权重可能保留它。

## 10. 已知偏差和风险

1. **特效缺口**：触发饰品只显示提示，不参与分数；这会让静态属性很弱但特效很强的饰品被低估。
2. **套装缺口**：当前比较的是单件属性，不知道穿上第 2/4/6 件后套装效果是否激活。
3. **护甲/武器映射维护成本**：AtlasLootMY 的职业分类数据会随客户端版本变化，bg次bis版 的 Titan 子类表需要独立校验，不能只复制一份现代客户端表。
4. **EP 时效性**：专用 EP 是一个版本和战斗模型下的起点，不应包装成永久正确的 BIS 排序。
5. **已镶宝石偏差**：整套战斗评级来自角色实时数据；若 Titan 的物品属性接口未返回旧装备上的宝石属性，移除旧装备时可能无法完整扣除这些评级。

| 纯攻强/破甲/精准戒指给法系职业 | 返回属性不适合，不因戒指通用而放行 |
| 纯格挡/闪避/防御/招架戒指给非坦克 | 返回属性不适合 |
| 混合戒指含 1 条禁用属性和 1 条有效属性 | 禁用属性计 0，仅按有效属性评分，并在明细中标记浪费 |
| 命中刚好达到门槛 | 缺口部分按 100%，不多算溢出 |
| 命中已经超过门槛 | 额外命中计 0 分，并给出说明 |
| 精准已经达到门槛 | 额外精准计 0 分，并给出说明 |
| 主坦防御达标 | 额外防御计 0 分 |
| 副坦防御 | 不做硬门槛，使用低防御权重 |
| 戒指/饰品双栏位 | 选择真实替换收益更高的栏位 |
| 单手/双持 | 不因另一栏位的当前装备导致错误比较 |
| 双手武器 | 候选和旧方案都按整套主副手替换计算 |
| 兑换物 | 评估所有可兑换成品，取最高可用分 |
| 唯一已装备 | 显示 `=`，升级分为 0 |
| Tooltip 尚未缓存 | 重试后得到真实属性，不永久缓存空值 |
| 自定义 EP | 只影响当前职责:天赋档案，不污染其他档案 |
